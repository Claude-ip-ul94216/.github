<p>「购买」在大多数人的理解里是一个动作：付钱、拿到线路、开始用。实际上它是四层叠起来的过程：计量层决定你怎么被收费，开通层决定你多久能拿到可用线路，验收层决定这条线到底能不能用，退订层决定你停掉之后还会留下什么。四层里任何一层没想清楚，都会在事后变成麻烦——比如淡季想停却被合约束住，或者停掉之后发现环境配置还绑在旧 IP 上。这篇把四层逐层拆开，每层给出具体的判断动作，最后附一张演示前的一小时验收清单。</p>

<h2>一、四层结构：计量、开通、验收、退订</h2>
<p>为什么按这个顺序分？因为它对应你从掏钱到不再使用的完整路径，而且四层的决策时机不同：计量在付款前定，开通在付款时触发，验收在拿到线路后一小时内完成，退订在下个账期前决定。错过时机的成本依次升高。</p>
<p>四层之间还有依赖关系。计量方式决定了你能不能随时停，开通速度决定了你能不能应急，验收结果决定了你要不要退，退订规则决定了你敢不敢试。把它们当成一个整体看，才不会被某一层的低价吸引。</p>
<p>下面逐层拆，每层只讲能落地的判断动作，不讲抽象原则。</p>

<h2>二、计量层：三种单位，三种自由度</h2>
<h3>按小时：最灵活，也最贵</h3>
<p>按小时计费适合不确定时长的场景，比如演示、临时压测、短期排查。优点是用完即停，缺点是单位时间成本通常最高，长时间挂着不划算。判断标准：预计使用时长低于每天四小时的，按小时更合适。</p>
<p>注意最小计费单位。有的按小时整点计，开十分钟也收一小时；有的按分钟折算。这一点在演示场景里差别很大，提前问清。</p>
<h3>按量与包月：把弹性换成单价</h3>
<p>按量（按 GB）适合流量波动大的业务，包月适合用量稳定、需要账面可预期的团队。淡季想停的场景，要重点看包月是否支持降配或暂停，很多方案只能等下个账期，等于把「随时停」这句话打了折扣。</p>
<p>采购时问三个具体问题：能否按天降配、暂停期间是否保留 IP、恢复时是否重新分配。第三个问题最关键——重新分配意味着地区可能变，之前配好的环境要重做。</p>

<h2>三、开通层：从下单到可用的三个时点</h2>
<h3>付款成功、分配完成、实际可用</h3>
<p>这三个时点经常被混为一谈。「当天开通」通常指付款后进入分配队列，实际拿到可用线路可能还要等。实测口径应该是：从付款成功到第一次成功通过该线路访问外网的时间差。</p>
<p>应急场景要把这个数字写进预案。如果你的容忍度是半小时，那开通时延超过半小时的方案就不能作为应急资源，无论它多便宜。</p>
<h3>批量开通的排队效应</h3>
<p>单条开通几分钟，批量开通可能是几分钟乘以批次。接口限流是主要原因，多数服务商对单账号的并发请求有限制。放量前先测一次批量开通的实际耗时，比如一次开十条，记录从提交到全部可用的时间。</p>
<p>这个数字决定了你的扩容速度。遇到突发需求时，如果一批十条要等两小时，那你的实际扩容能力就是每小时五条，不是「想开多少开多少」。</p>

<h2>四、验收层：一小时跑完的五项</h2>
<h3>归属、延迟、断线、地区、会话</h3>
<p>一小时足够做完五项检查，顺序不要乱。先查归属（ASN 与类型），再看延迟（连续压 60 秒看 P95），然后观察断线（挂 20 分钟看是否重拨），接着确认地区（与预期是否一致），最后测会话（登录一次，看是否被要求额外验证）。</p>
<p>五项全部通过才算可用。任何一项不过，立刻找服务商换线，不要试图调参补救——验收阶段的调参，等于把问题带到生产环境。</p>
<h3>演示前的加急版</h3>
<p>如果是为了当天给客户演示，验收可以压缩到二十分钟，但必须保留三项：归属查询、地区确认、一次完整登录。演示最怕的是出口类型不对或者地区漂移，这两项查完，剩下的风险就不大了。</p>
<p>演示前建议提前一小时开通并跑通全流程，而不是临开始才开。一小时的余量足够处理大部分意外，比如线路分配慢、登录要额外验证。</p>

<h2>五、退订层：停掉之后还留着什么</h2>
<h3>三样东西需要清理</h3>
<p>一是环境与线路的绑定关系。停掉线路后，配置表里对应行要标记失效，否则下次启动会连到一个已经不存在的地址。二是浏览器环境目录里的登录状态。如果这个环境以后不再用，目录应该归档而非留在原位，避免被误用。三是本地的代理规则和 hosts 记录，容易残留导致后续流量走错。</p>
<p>这三样清理起来不超过半小时，但不清理的后果是持续性的：后面排查问题时会遇到一堆已失效的配置，分不清哪些还有效。</p>
<h3>停掉会不会影响账号</h3>
<p>停线路本身不影响账号状态，但重新开通后出口 IP 大概率变化，等于一次地区变更。如果账号需要长期稳定地区，淡季建议保留最低配置，而不是完全停用。这是「随时停」这句话最容易被忽略的代价。</p>

<h2>常见问答</h2>
<h3>按小时计费能不能用来做长期使用？</h3>
<p>答：技术上可以，经济上不划算。按小时的单价通常是包月的数倍，连续用一个月成本会高出很多。它适合的是短时、不确定时长的场景，比如演示、临时压测、故障应急。</p>
<h3>淡季停掉，旺季再开，出口会变吗？</h3>
<p>答：大概率会。停用期间资源会被回收，重新开通时分配到的 IP 和地区都可能与原来不同。如果账号对地区敏感，建议淡季保留最小配置，或者提前问清是否有「保留 IP」的选项。</p>
<h3>演示前一小时开通，来得及吗？</h3>
<p>答：多数情况下来得及，但要留出处理意外的余量。开通时延在 30 分钟内的方案比较稳妥；如果对方说要等几小时，就别把它用在演示上。另外提前准备好一条备用线路，比赌时间更可靠。</p>
<h3>验收发现出口类型不对，能要求换吗？</h3>
<p>答：验收阶段提出更换是合理的，也是验收存在的意义。建议在采购前就把「出口类型与描述不符可换」写进约定，避免事后扯皮。换线时要重新走一遍五项验收，不要因为换过一次就省略。</p>
